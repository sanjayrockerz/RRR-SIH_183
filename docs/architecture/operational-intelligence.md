# Operational intelligence

RRR's command center uses backend-owned read models rather than deriving investigative priority in React.

## Dashboard intelligence

`GET /api/v1/dashboard/intelligence` aggregates persisted cases, latest risk assessments, active watches, alerts, exact case overlaps, cross-chain links, graph-edge attribution, and investigation timeline events. Priority ordering is deterministic: critical posture, high posture, active watch, source-backed VASP lead, open critical alert, positive risk delta, then latest activity. A missing signal is represented as `null`, `0`, or `NO DATA` at the UI boundary; it is never fabricated.

## Case intelligence snapshot

`GET /api/v1/cases/{case_id}/intelligence` composes the existing case summary, risk factors, risk delta, patterns, attribution, cross-chain summary, exact related-case links, watch state, latest timeline/alert, and structured rule-based recommendations. It is a read model only and does not call providers or replace the underlying services.

## VASP actionability

`GET /api/v1/cases/{case_id}/vasp-candidates` ranks source-backed VASP, exchange, and custodial-service observations by shortest persisted path, attribution confidence, source quality, and observed path flow. `POST /api/v1/cases/{case_id}/vasp-action-package` reuses `ReportService` and the evidence ledger to create an immutable report snapshot and, when evidence exists, a SHA-256 evidence manifest. It recommends investigator review for appropriate coordination; it does not freeze assets or assert ownership.

## Risk Registry

`GET /api/v1/risk-registry/search` searches persisted wallets, entities/VASPs, cases, and transactions. Entries expose observed case history, risk posture, roles, related VASP records, connected cases, and evidence count. The registry is internal investigative memory, not a blacklist; no criminal classification is generated by the search.

## Factual and derived boundaries

- On-chain transactions, graph edges, evidence, watch events, and persisted case overlap are observations.
- Entity/VASP attribution is source-backed only when a curated attribution record exists.
- Risk, priority, recommendations, and cross-chain correlation are derived investigative assessments.
- Future ML prediction is not represented by these contracts.

## Known limitations

VASP lead counts require persisted graph edges and curated address attribution. Cross-chain counts require persisted cross-chain links. The read models report database/provider failure through the existing API error boundary and do not fall back to in-memory or hardcoded data. Case-level authorization is still pending the existing authentication/RBAC deployment work.
