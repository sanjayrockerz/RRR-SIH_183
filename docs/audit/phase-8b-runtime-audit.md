## Explicit UI-only or incomplete behavior found

- The legacy `Dashboard` component contains unused hardcoded display values; the active route uses `LiveDashboard`.
- Intake source is encoded into description and NCRP/SAHYOG remain simulated adapters; no external complaint API is connected.
- Global search is a visual input without a backend search operation.
- Wallet page is persisted-observation lookup, not live wallet intelligence.
- Graph edge inspection can copy a hash but cannot open a transaction detail workspace.
- Case context is kept in React memory and is lost on a full page reload unless reopened from Cases.
- Realtime live watch creation is correctly credential-gated; simulated mode is explicit but database-dependent.

## Runtime findings

- API startup succeeds in degraded mode without PostgreSQL.
- `/api/v1/system/status` reports `UNAVAILABLE` for PostgreSQL with `InvalidPasswordError`.
- PostgreSQL Windows service is running, but the configured `postgres/postgres` credentials do not authenticate.
- Docker Desktop Linux engine is unavailable, so the Compose PostgreSQL/Neo4j stack cannot be started here.
- Backend unit/contract suite and frontend build pass; database integration tests remain skipped without `RUN_POSTGRES_TESTS=1` and working credentials.

## 8B priority order

1. Make case workflow stages and acquisition results persistent and visible.
2. Add provider health/provenance and transaction/evidence detail APIs.
3. Connect attribution, sanctions and realtime outcomes into case state/timeline.
4. Make realtime event pipeline stages inspectable and add bounded watch expansion.
5. Add global alert/evidence/report deep links and command-center data.
6. Validate PostgreSQL, Alchemy, TronGrid and Neo4j with configured environments.
