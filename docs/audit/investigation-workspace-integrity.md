# Investigation Workspace Integrity Audit

Date: 2026-08-28

This audit traces the existing RRR investigation workspace from frontend route to API, service, repository, PostgreSQL source, frontend state, and rendered component. It does not assume behavior from the UI alone.

| Module | Route | API | Database source | Status | Current failure | Fix required |
| --- | --- | --- | --- | --- | --- | --- |

Root causes confirmed:

- The frontend route model remained flat (`#graph`, `#risk`, `#monitoring`), so module URLs did not themselves contain the active `case_id`.
- The legacy document click handler previously rewrote case tab clicks through global dashboard labels. It is now bypassed for `.case-tabs`; this pass makes tab navigation case-scoped as well.
- `GET /api/v1/cases/{case_id}/transactions` reads real PostgreSQL rows but did not expose risk, pattern, or entity joins, so the ledger and transaction drawer could only render decorative intelligence.
- `RiskPage` did not load persisted risk history/factors unless the current assessment existed and its mount effect did not depend on the active case/trace, so a restored route could remain stale.
- Case-scoped Entities/VASP, Threat Intelligence, Sanctions, Fund Flow, and Timeline workspaces were either global pages or absent; they need honest persisted/unknown states, not new mock dashboards.
- Database health is already available from backend diagnostics. Frontend copy must use those diagnostics and avoid deriving persistence state from zero cases.
